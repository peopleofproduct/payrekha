# Production-readiness action plan — the path to "best-in-industry, plug-and-play"

_Working plan. Source: the CIAD-2026-0058 line-by-line review (`advisory-review-ciad-2026-0058.md`), the current codebase at `0.1.0-alpha.2`, and the target stakeholder set the advisory itself names: NBFCs, digital lending platforms, fintech entities, payment aggregators, payment service providers, and crypto/VDA service providers._

## Goal and principles

**Goal:** any of the named stakeholder types can take PayRekha from download → enforce-mode production with minimal integration effort, provable advisory coverage, and no surprises for their auditors.

**Principles (kept deliberately):**

1. **Do one thing perfectly.** PayRekha is the last check before money leaves. It does not become an EDR, SIEM, ML platform or hosted service. "Best in industry" = the strongest money-path control + honest boundaries, not feature sprawl.
2. **Every claim is evidence-backed.** Coverage means code + tests + demo, documented — the review doc is the template.
3. **Plug-and-play is measured in time-to-value.** Replay in ~10 min, live shadow in ~30 min (already true), enforce-capable on one kind within one sprint — without writing code where avoidable.
4. **Advisory-driven backlog.** Gaps are ranked by what CIAD-2026-0058 and its successors demand, then by stakeholder friction.
5. **Fail-safe invariants are non-negotiable.** Zero runtime deps in core/rules, no network calls, shadow-first, degraded-never-allow, hashed identifiers only. Every item below must preserve them.

## What we deliberately do NOT do

Staying honest about the boundary is part of "best in industry" — the review shows buyers respect a control that knows its edges:

- No hosted/managed service, no phone-home — customers run it inside their walls (regulatory requirement anyway).
- No ML scoring — deterministic, explainable verdicts only (`riskScore` stays a triage number, not a model).
- No EDR/cloud/endpoint/network controls — we _integrate_ with them (SIEM/SOAR/Envoy), we don't become them.
- No CERT-In IoC consumption — restricted indicators stay out; behaviour+authorization is the durable defence (and the advisory's own advice).
- No UI-first product surface — the console (B2) serves operators; the product stays an embeddable control.
